# Adding i18n

For most projects, **react-i18next** is the right choice: mature, huge ecosystem, works with Suspense. Use **Lingui** if you prefer message-id-free syntax and compile-time extraction.

## react-i18next quick setup

```bash
pnpm add i18next react-i18next
```

Create resources:

```ts
// src/i18n/index.ts
import i18n from 'i18next';
import { initReactI18next } from 'react-i18next';

import en from './locales/en.json';
import es from './locales/es.json';

void i18n.use(initReactI18next).init({
  resources: { en: { translation: en }, es: { translation: es } },
  lng: 'en',
  fallbackLng: 'en',
  interpolation: { escapeValue: false },
});

export default i18n;
```

Import once, at the top of `src/main.tsx`:

```tsx
import '@/i18n';
```

Use in components:

```tsx
import { useTranslation } from 'react-i18next';

export function Greeting() {
  const { t } = useTranslation();
  return <h1>{t('greeting.hello')}</h1>;
}
```

## Testing

`useTranslation` returns the key when no translation is found. Tests that assert on user-visible copy should switch to a small message-key mock so they don't depend on translation files. Alternatively, wrap your tests in `<I18nextProvider>` with a minimal `en` bundle.
