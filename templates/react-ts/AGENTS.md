# AGENTS.md

Guidance for AI coding agents (Claude Code, Cursor, Codex, Aider, and similar) working in this project. It was scaffolded with [`create-atomic-react`](https://www.npmjs.com/package/create-atomic-react) (SPA variant): React 19 + TypeScript + Vite, TanStack Router + Query, Tailwind CSS v4, MSW, Storybook, Vitest + jest-axe, Playwright, PWA and Sentry.

Commands below use `pnpm`. If the project uses npm or yarn, substitute it - the git hooks in `.husky/` also call `pnpm`, so update them too.

## Component conventions

Every component lives at `src/components/{atoms,molecules,organisms,templates}/<Name>/` and ships four files:

```
<Name>.tsx           the component
<Name>.test.tsx      Vitest + RTL, MUST include an axe assertion
<Name>.stories.tsx   Storybook story with autodocs tag
index.ts             barrel: export { <Name> } + export type { <Name>Props }
```

Page components live at `src/pages/<Name>/` and additionally ship:

```
e2e/<Name>.spec.ts       Playwright spec with axe scan
src/routes/<slug>.tsx    TanStack Router file route
```

**Never hand-scaffold.** Use the generator:

```bash
pnpm generate                              # interactive
pnpm generate --kind atom --name Badge     # non-interactive
pnpm generate --kind page --name Dashboard
```

The generator writes all files with an axe assertion in the test template so accessibility never regresses. It does not check for collisions with existing routes - pick a page name that isn't already a route. After generating a page, run `pnpm dev:app` once so the router plugin regenerates `src/routeTree.gen.ts`; until then `pnpm typecheck` fails on the new route.

## Routing

- File routes in `src/routes/*.tsx` - 3-line `createFileRoute` calls. Do not add unit tests here; Playwright covers them end-to-end.
- `src/routeTree.gen.ts` is generated by the TanStack Router Vite plugin. Commit it, never edit it by hand.
- The root route (`src/routes/__root.tsx`) holds the layout, `errorComponent` and `notFoundComponent`.
- Validate search params with zod in the route file and read them with `Route.useSearch()`.
- Links: `<Link to>` from `@tanstack/react-router`, not `<a href>` for internal routes.

## Testing patterns

- Unit tests: import `axe` from `jest-axe`, assert `expect(await axe(container)).toHaveNoViolations()`. The matcher is registered globally in `src/test/setup.ts` and typed in `src/test/a11y.d.ts`.
- To test a component that uses `<Link>` or `useNavigate`, mock the router at the top of the file:

  ```ts
  vi.mock('@tanstack/react-router', () => ({
    Link: ({ to, children, ...rest }) => <a href={to} {...rest}>{children}</a>,
    useNavigate: () => vi.fn(),
  }));
  ```

- Components that render `<PwaUpdate>` (e.g. `MainLayout`) need `virtual:pwa-register/react` mocked. Storybook stubs it in `.storybook/stubs/pwa-register.js`.
- E2E: use `AxeBuilder` from `@axe-core/playwright` with the standard WCAG tag set - see `e2e/a11y.spec.ts` for the loop pattern.
- MSW handlers in `src/mocks/handlers.ts` are the single source of truth for Vitest, Storybook, dev, and Playwright. MSW only starts in dev (`src/main.tsx`).

## Where things live

- Entry: `src/main.tsx` initialises Sentry, starts MSW in dev, then mounts the router.
- Providers: `src/providers/` - wrapper providers get unit tests, no stories (a wrapper story teaches nothing).
- Context modules like `theme-context.ts`: exercised through the provider that consumes them, no standalone test.
- Data fetching: TanStack Query, client in `src/lib/query-client.ts`; HTTP helper in `src/lib/api.ts`.
- Env parsing: `src/lib/env.ts` - extend the zod schema, copy the new var into `.env.example`. Only `VITE_*` vars reach the browser; never put secrets in them.
- The docs page at `/docs` uses `?raw` imports so its code snippets are always in sync with the actual source. Follow the same pattern if you extend it.
- SEO: every page should render `<Seo title="…" siteName="…" description="…" />` at the top of its JSX. The `Seo` atom (`src/components/atoms/Seo/`) emits title + description + canonical + Open Graph + Twitter card tags via React 19's native `<head>` hoisting - do NOT install `react-helmet-async`. These tags are added client-side, so link-preview bots that don't run JavaScript won't see them.
- Sitemap: `scripts/generate-sitemap.mjs` runs as part of `pnpm build` and writes `dist/sitemap.xml` derived from `src/routes/`. Set `VITE_SITE_URL` in the shell environment for the build, otherwise URLs default to `https://example.com`. Dynamic routes (`$slug.tsx`) are skipped. Robots at `public/robots.txt`.
- PWA: `vite-plugin-pwa` is configured in `vite.config.ts` (via `loadEnv`, so manifest name pulls from `VITE_APP_TITLE`). `<PwaUpdate>` is rendered inside `MainLayout` and uses `virtual:pwa-register/react`. `registerType: 'prompt'` shows a reload toast; switch to `autoUpdate` for silent updates. Dev server has the SW disabled (`devOptions.enabled: false`).
- Sentry: init helper at `src/lib/sentry.ts`. No-op unless `VITE_SENTRY_DSN` is set, and always inert in dev (`enabled: !import.meta.env.DEV`). To capture route-level errors, import `Sentry` from `@/lib/sentry` and call `Sentry.captureException(error)` inside the root route's `errorComponent`.
- Deploy: `pnpm deploy` shells out to `aws s3 sync --delete` - needs the AWS CLI on PATH. Entry-point files (`index.html`, `sw.js`, `manifest.webmanifest`, `robots.txt`, `sitemap.xml`) get `max-age=0,must-revalidate`; everything else gets `max-age=31536000,immutable`. For S3-compatible providers, pass `--endpoint <url>` or set `DEPLOY_ENDPOINT`. CDN base URL for assets: `VITE_BASE_URL` at build time. Netlify (`netlify.toml`) and Vercel (`vercel.json`) configs are included.
- Shared configs: ESLint, tsconfig, Vitest and Playwright extend the `@react-app-boilerplate/*` packages. Override locally in the project's own config files rather than forking the packages.
- Task skills for Claude Code: `.claude/skills/` (generate-component, add-msw-handler, add-env-var, add-seo, configure-pwa, configure-sentry, configure-deploy).

## Demo code

Every example file starts with `// EXAMPLE - safe to delete` and lives under `src/**/example/` (plus the `/docs`, `/example` and `/watch` routes). Run `pnpm strip-example` (preview with `--dry-run`) to remove it all before building the real app. Don't model new features on the demo's file layout - use the generator.

## Commit + PR style

- Conventional Commits enforced by commitlint on `commit-msg`. Types: feat, fix, docs, style, refactor, perf, test, build, ci, chore, revert.
- Keep subject lines short (under ~70 chars). Put detail in the body.
- Do not skip hooks (`--no-verify`) - the pre-commit runs lint-staged (ESLint + Prettier) on staged files only.

## What to avoid

- Hand-scaffolding components without the four-file set
- Skipping the axe assertion in generated tests
- Installing `react-helmet-async` - use the `Seo` atom
- Using `<a href>` for internal links - use `<Link to>`
- Editing `src/routeTree.gen.ts` by hand
- Committing the `.tanstack/` folder (gitignored) or `.env` files (only `.env.example` is committed)
- Adding a comment that explains WHAT code does - only WHY, when non-obvious
